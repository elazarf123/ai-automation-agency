The Problem

Clearwater Advisors (name anonymised) manages bookkeeping and accounts-payable for 40+ SMB clients across retail, logistics, and professional services.

Each client sends anywhere from 20 to 80 invoices per month — arriving via email as PDFs, Word docs, photos, and scanned faxes. Staff were manually opening each one, extracting vendor name, date, line items, totals, and GL codes, then entering them into QuickBooks.

The process was consuming 3 full working days per week across two bookkeepers. Despite their care, manual transcription errors crept in at a rate of around 4% — enough to cause reconciliation headaches at month-end. And when invoice volume spiked, the backlog grew to 3–4 days, delaying client reports.

⚙️

The Solution

We built an end-to-end invoice processing pipeline using the Claude AI API for document understanding, integrated with their existing email inbox, Make.com for orchestration, and QuickBooks Online for entry.

How It Works

  1. 1. Invoice arrives via email or file upload
  2. 2. AI extracts all fields (vendor, date, line items, totals, tax)
  3. 3. GL codes auto-assigned based on vendor history
  4. 4. Confidence check: 95%+ auto-posted to QuickBooks
  5. 5. Low-confidence invoices flagged for 30-second human review

What It Handles

  • ✓ Multi-page PDF invoices
  • ✓ Scanned / photographed documents
  • ✓ Multi-vendor, multi-currency
  • ✓ Duplicate invoice detection
  • ✓ PO matching & three-way match
  • ✓ Automatic GL code assignment
  • ✓ Direct export to QuickBooks
📅

Implementation Timeline

Days 1–3

Audit & Design

Reviewed 100 sample invoices, mapped GL code logic, obtained QuickBooks OAuth credentials, designed confidence threshold model.

Days 4–10

Build & Integration

Built Make.com pipeline, configured Claude extraction prompts for all invoice formats, connected to QuickBooks API, set up human review queue for edge cases.

Days 11–14

Testing & Launch

Processed 200 real invoices in parallel with manual process to validate accuracy. Achieved 96.2% match rate. Went fully live on Day 14.
