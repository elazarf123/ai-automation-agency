# Make.com Setup Guide — Enterprise IT Automation Scenarios

Step-by-step instructions for configuring Make.com (formerly Integromat) to orchestrate PowerShell-based enterprise workflows.

---

## Prerequisites

| Requirement | Details |
|-------------|---------|
| Make.com account | Free tier works for testing; Core or higher for production use |
| PowerShell endpoint | A publicly reachable HTTPS endpoint running your scripts (Azure Function, AWS Lambda, IIS, or ngrok for local dev) |
| Webhook secret | A shared secret string used to authenticate requests between Make.com and PowerShell |
| SMTP / SendGrid | For email notification modules |

---

## Part 1: Creating a Webhook Trigger

### 1.1 Add a Custom Webhook Module

1. Open Make.com and click **Create a new scenario**.
2. In the trigger position, search for **Webhooks** and select **Custom webhook**.
3. Click **Add** to create a new webhook.
4. Enter a descriptive name, e.g. `User Provisioning — New Hire Form`.
5. Click **Save** — Make.com generates a unique webhook URL.

### 1.2 Configure the Webhook URL in Your Web Form

Copy the generated URL and paste it into your web form's `action` attribute or JavaScript `fetch` call:

```javascript
// dashboard.js — see /demo/dashboard.js
const MAKE_WEBHOOK_URL = "https://hook.us1.make.com/YOUR_UNIQUE_WEBHOOK_ID";

async function submitProvisioningForm(formData) {
  const response = await fetch(MAKE_WEBHOOK_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(formData)
  });
  return response.json();
}
```

### 1.3 Set a Webhook Secret Header

For security, add a custom header validation:

1. In the webhook settings, click **Show advanced settings**.
2. Under **IP restrictions**, optionally whitelist known IPs.
3. In your PowerShell script, validate the `X-Webhook-Secret` header:

```powershell
# Validate incoming webhook secret
$incomingSecret = $Request.Headers["X-Webhook-Secret"]
if ($incomingSecret -ne $env:WEBHOOK_SECRET) {
    Push-OutputBinding -Name Response -Value ([HttpResponseContext]@{
        StatusCode = [HttpStatusCode]::Unauthorized
        Body = "Invalid secret"
    })
    return
}
```

## Part 2: Configuring the HTTP Module (Make.com → PowerShell)

### 2.1 Add an HTTP Module

1. After the webhook trigger, click **+** to add a module.
2. Search for **HTTP** and select **Make a request**.
3. Configure as follows:

| Field | Value |
|-------|-------|
| URL | `https://your-endpoint.azurewebsites.net/api/Invoke-AutomationWebhook` |
| Method | `POST` |
| Headers | `X-Webhook-Secret: {{your_secret}}` |
| Body type | `Raw` |
| Content type | `application/json` |
| Request content | Map fields from the webhook trigger |

### 2.2 Sample Request Body (JSON)

```json
{
  "action": "NewUser",
  "firstName": "{{1.firstName}}",
  "lastName": "{{1.lastName}}",
  "department": "{{1.department}}",
  "manager": "{{1.manager}}",
  "startDate": "{{1.startDate}}",
  "license": "{{1.license}}"
}
```

> **Note**: The `{{1.fieldName}}` syntax maps data from the preceding webhook module (module 1).

## Part 3: Setting Up a Data Store

Make.com's built-in Data Store acts as a lightweight database for logging automation requests.

### 3.1 Create a Data Store

1. Go to **Data** → **Data stores** → **Add data store**.
2. Name it `AutomationLogs`.
3. Define the following structure:

| Field Name | Type | Notes |
|------------|------|-------|
| `requestId` | Text | UUID generated by Make.com |
| `action` | Text | e.g., `NewUser`, `StaleCheck`, `LicenseAudit` |
| `status` | Text | `pending`, `completed`, `failed` |
| `payload` | Text | JSON string of the original request |
| `result` | Text | JSON string of the PowerShell response |
| `createdAt` | Date | Timestamp of the request |
| `completedAt` | Date | Timestamp of completion |

### 3.2 Log a Request (Add a Record)

Add a **Data Store → Add a record** module after the webhook trigger:

```
requestId:  {{uuid()}}
action:     {{1.action}}
status:     pending
payload:    {{toJSON(1)}}
createdAt:  {{now}}
```

### 3.3 Update a Record After Completion

After the HTTP module responds, add a **Data Store → Update a record** module:

```
Key:          {{requestId from step 2}}
status:       completed
result:       {{toJSON(3.body)}}
completedAt:  {{now}}
```

## Part 4: Configuring Email Notifications

### 4.1 SendGrid Module Setup

1. Add a **SendGrid → Send an email** module at the end of the scenario.
2. Create a SendGrid API key at [sendgrid.com](https://sendgrid.com) and add it in Make.com **Connections**.
3. Configure:

| Field | Value |
|-------|-------|
| From | `automation@yourcompany.com` |
| To | `{{1.managerEmail}}` (mapped from form data) |
| Subject | `New User Provisioned: {{1.firstName}} {{1.lastName}}` |
| Body | Use the HTML template below |

### 4.2 Email Body Template

```html
<h2>User Provisioning Complete</h2>
<p>The following account has been created successfully:</p>
<table>
  <tr><td><strong>Name</strong></td><td>{{firstName}} {{lastName}}</td></tr>
  <tr><td><strong>Username</strong></td><td>{{samAccountName}}</td></tr>
  <tr><td><strong>Email</strong></td><td>{{email}}</td></tr>
  <tr><td><strong>Department</strong></td><td>{{department}}</td></tr>
  <tr><td><strong>Start Date</strong></td><td>{{startDate}}</td></tr>
</table>
<p>Provisioned by AutomateIQ Automation System at {{completedAt}}</p>
```

## Part 5: Scheduling Scenarios

For recurring tasks like stale account detection and license audits:

1. Replace the **Custom Webhook** trigger with a **Scheduler** module.
2. Configure the interval:
   - **Stale Account Detection**: Every week on Monday at 08:00 AM
   - **License Audit**: Every month on the 1st at 07:00 AM
3. Set the timezone to match your organisation.
4. Enable **Run scenario immediately** for the first test run.

---

## Part 6: Error Handling

### 6.1 Add an Error Handler Route

1. Right-click any module and select **Add error handler**.
2. Choose **Rollback** (for transactional operations) or **Commit** (to log and continue).
3. Add a **Slack** or **Email** module in the error route to alert the team.

### 6.2 Configure Incomplete Executions

1. Go to **Scenario settings** (spanner icon).
2. Enable **Allow storing incomplete executions**.
3. This lets you manually re-run failed scenarios from **Incomplete executions** in the dashboard.

## Part 7: Testing Checklist

- [ ] Send a test POST to the webhook URL using Postman or `curl`
- [ ] Verify the webhook module receives the payload correctly
- [ ] Check the Data Store for the `pending` log entry
- [ ] Confirm the HTTP module sends the correct JSON to your PowerShell endpoint
- [ ] Validate PowerShell processes the request and returns a `200 OK` with JSON
- [ ] Verify the Data Store record is updated to `completed`
- [ ] Confirm the email notification is received by the correct recipient
- [ ] Review the Make.com execution log for timing and any warnings
